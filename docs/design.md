# 市场波段温度计 —— 设计文档 v2.0（A股 MVP）

> 基于 v1.0（与 Gemini 讨论稿）评审修订。主要变化：估值层 / 择时层拆分、全指标统一分位化、
> 去掉阶跃式共振修正、状态机补齐失效/冷却/降级规则、数据源按实测结果替换。
> 本文中所有阈值均为**初始值**，必须经回测校准后才可用于实盘提醒。

---

## 1. 目标与范围

- **目标**：识别 A股宽基指数的阶段性相对低点 / 高点，辅助大波段仓位管理；不做日内、不做个股。
- **MVP 范围**：单市场（A股，标的 沪深300）、免费数据源、可插拔数据源插件层、SQLite、**Web 界面（主要交互方式）**、回测、4 种推送渠道；CLI 仅作辅助。
- **非目标（首期不做）**：美股（第二阶段，但插件层和市场定义需为其预留）、付费数据源（有收益后再接入）、自动交易。

**stockdb 数据质量（2026-11-25 抽样）**：历史数据可靠；当日数据为临时值（盘后 15:00 更新、24:00 校对），近 5 日收盘价多处与腾讯不一致；
个别股票有缺口（600000 缺 2026-06-25～07-02，2026-11-25 已用腾讯补齐；同期 002731、688121 等 6 只自 05-06 起的缺口经腾讯核实为停牌）；场内基金历史不完整（510300 只有 2024 年起）。→ 每次同步重拉最近约 10 个交易日；基金优先用腾讯。

**实测中发现的坑：**
1. **东财 `push2his` 限流严重**：连续约 50–60 次请求后，连接被服务端断开（HTTP 000），约 90 秒后恢复；
   降速到每秒 1 次仍然失败 75%（150 次里成功 37 次）。`push2`、`datacenter` 不受影响。
   **封禁会升级**：上午压测后，到 12:00 仍被封（超过 1 小时），4 次指数 K 线请求也拿不到。
   → 插件对 push2his 不做重试，失败后 10 分钟内短路，交给路由回退；**任何核心指标都不应只依赖 push2his**。
   → **个股历史回填改用腾讯 `fqkline`（主源）**：实测 200 次连续请求全部成功，约 0.4 秒/次；
   单次最多 640 根，约 6 次/股，6,500 只约 4 万次请求，串行约 4.5 小时，2–4 并发约 1–2 小时，只做一次。
   东财 `push2his` 只用于少量指数 K 线（每日个位数次请求）。每日增量改用 `push2` 快照（约 60 次请求）。
2. **PE 口径**：11-24 沪深300 三个来源的数值不一致：中证 `peg`=13.06、中证估值 xls（静态）P/E1=13.75 / P/E2=14.92、蛋卷=13.46。
   `peg` 大概率是 TTM 口径。因为只用分位，**关键是始终使用同一来源**；切换来源时必须重新计算历史分位。
   PE 空值只集中在 2011–2012 年（66 天），之后连续。
3. **盘中未完成 K 线**：上午 10:53 请求时，东财已返回当日（11-25）的 bar。完整性检查必须在 15:30 以后进行，且只接受 `trade_date < 今天`，或当日收盘后的数据。
4. **中证接口包含非交易日行**（如 20000101）：所有序列以沪深300 东财日线的交易日为准做对齐。
5. **当日 PE 的发布时间未知**：当前 11-24 的数据可取，11-25 盘中不可取。保守起见，V 层使用 T-1 的 PE，回测同口径。

**回测起点**：见 §3.4 的预热期分析。

## 3. 指标体系：两层结构

### 3.1 统一归一化：滚动分位

所有指标都用同一个算子映射到 `[0,100]`。0 代表极冷、便宜，100 代表极热、昂贵。

```
pct(x_t; W, minW) = (count(x_i < x_t) + 0.5 * count(x_i == x_t)) / n * 100
  窗口取 [t-W+1, t]，仅用 t 时刻及以前的数据；n = 实际样本数；n < minW 时输出 NULL（预热期）
反向指标：score = 100 - pct
```

### 3.2 估值层 V（慢变量，只做背景，不直接出信号）

- `ERP_t = 1 / PE_TTM(沪深300) - Y10_CN / 100`
- `PE_TTM` 和 `Y10_CN` 均取 T-1 的值（§2 坑 5）。
- `V_t = 100 - pct(ERP_t; W=2520 交易日约 10 年, minW=500)`，ERP 越高越便宜，V 越低。
  采用扩展窗口：样本少于 2520 时用全部可得历史；预热期分析见 §3.4。
- 分三档：**便宜** `V ≤ 30`｜**合理** `30 < V < 70`｜**昂贵** `V ≥ 70`
- **滞回**（M3 加入）：离开便宜需 `V > 30 + 5`，离开昂贵需 `V < 70 − 5`。不加滞回时 2013 年以来估值档切换 118 次，加入后为 50 次。
- 作用：调节择时层的武装阈值，见 §4.3；推送时展示估值背景。

### 3.3 择时层 T（快变量，出波段信号）

| 维度 | 原始值 | 预处理 | 方向 | 窗口 |
|---|---|---|---|---|
| T1 资金热度 | 按金额换手率 = 中证全指成交额(T) / 全A流通市值(T-1) | 5 日均值；流通市值变化慢，用 T-1 不影响时效 | 正向 | W=750，minW=250 |
| T2 杠杆情绪 | 融资买入额 / 中证全指成交额（同日） | 5 日均值，**整体使用 T-1 数据**（两融 T+1 发布） | 正向 | W=750，minW=250 |
| T3 市场广度 | 全A中 `Close > MA200` 的占比（后复权） | 剔除上市不足 200 日、停牌个股 | 正向 | W=750，minW=250 |
| T4 价格动量 | `R_mix = 0.4·RSI_d(14) + 0.6·RSI_w(14)` | Wilder 平滑；周线用"截至当日"的动态周 K | 正向 | W=750，minW=250 |

- 合成：`T_base = Σ w_k · T_k`，初始**等权** `w_k = 0.25`，避免先验调参造成过拟合。
- 二次分位：`T_pct = pct(T_base; W=750, minW=250)`，让 20/80 阈值在历史上有稳定的含义。
- 平滑：`T_s = EMA(T_pct, 3)`，状态机只看 `T_s`。
- 共振计数：`N_low = #{T_k ≤ 20}`、`N_high = #{T_k ≥ 80}`。**只作为武装的附加条件和展示信息，不再乘系数修改分数**（v1 的 ×0.85 / ×1.15 是阶跃函数，会制造假拐点）。
- 回测对照候选（不进 MVP 默认配置）：布林 %B、MA60 乖离率，可以替换 T4 做对比。
- 回测报告必须输出 T1–T4 两两相关系数，如果某两维相关系数 > 0.8，就考虑合并。

### 3.4 预热期与有效回测区间（已确认：方案 B）

各序列的原始数据起点约为 2011 年中，每层窗口都会消耗预热时间：

| 方案 | 预热设置 | V 可用起点 | T_s 可用起点 | 有效回测区间 | 代价 |
|---|---|---|---|---|---|
| A 满窗（v2 初稿） | V minW=1250；T_k / T_pct 各 minW=500 | ~2016-06 | ~2015-08 起，叠加二次分位约到 2017 | **约 2016/2017 至今** | 丢掉 2015 年牛熊；信号样本约 10 个 |
| **B 扩展窗口（推荐）** | V minW=500；T_k、T_pct minW=250，扩展到满窗 | ~2013-06 | ~2012-05（T1/T2 起点 2010-03） | **2014 至今** | 早期分位样本少、噪音大 |
| C 去掉二次分位 | 同 B，但直接对 `T_base` 设阈值 | ~2013-06 | ~2012-10 | 2013 至今 | 20/80 阈值的含义随时间漂移 |

采用 B（2026-11-25 确认），并在回测报告中附带对照：2017 年以后的信号在 A、B 两种窗口设置下是否基本一致。
如果一致，说明短预热期没有扭曲结论。

### 3.5 缺失与降级

- 单维缺失时，剩余维度按权重重归一化，当日标记 `degraded=true`。
- **降级日不触发新信号**（状态照常推进），推送中注明"数据不完整"。
- 缺失 ≥ 2 维时不计算 T，当日跳过。
- PE、利率这类慢变量允许前值填充，最多 5 个交易日。
- **未启用的维度不算降级**：维度是否启用由参数集决定（例如广度在 M4 之前不启用，T 按 T1/T2/T4 三维等权）。
  降级只针对"已启用但当日缺数"的情况。

## 4. 状态机

### 4.1 设计原则

- **纯函数**：`state_t = step(state_{t-1}, obs_t, params)`。回测和实盘共用同一份代码；数据库里的 state 只是缓存，任何时候都可以从历史回放重建。
- 只用 `T_s`（平滑后）判断，阈值均为参数。

### 4.2 状态与转移

```
状态：IDLE | BOTTOM_ARMED | TOP_ARMED | BOTTOM_COOLDOWN | TOP_COOLDOWN
追踪量：armed_since, min_ts, price_at_min, max_ts, price_at_max

底部
  IDLE → BOTTOM_ARMED      : T_s ≤ arm_low(V) 且 N_low ≥ 2
  BOTTOM_ARMED 中          : 持续更新 min_ts、price_at_min（T_s 最低当日的收盘价）
  BOTTOM_ARMED → 触发 BUY  : 满足下面任一条件
     a) 右侧回暖：T_s ≥ min_ts + 8 且 T_s 连续 2 日上升
     b) 底背离：  close < price_at_min（价格创本轮新低）且 T_s ≥ min_ts + 5
  触发后 → BOTTOM_COOLDOWN
  BOTTOM_ARMED → 失效      : T_s > 50 → IDLE；武装超过 60 个交易日未触发 → BOTTOM_COOLDOWN
                             （超时时 T_s 往往仍在冰点区，直接回 IDLE 会当日重新武装，M3 单测发现）
  BOTTOM_COOLDOWN → IDLE   : T_s > 35（回到中性才允许再次武装，防止反复触发）

顶部（对称）
  IDLE → TOP_ARMED         : T_s ≥ arm_high(V) 且 N_high ≥ 2
  触发 SELL                : a) T_s ≤ max_ts - 8 且 RSI_d(14) < 70
                             b) 顶背离：close > price_at_max 且 T_s ≤ max_ts - 5
  失效                     : 超过 60 个交易日，或 T_s < 50
  TOP_COOLDOWN → IDLE      : T_s < 65
```

### 4.3 估值层调节

| 估值档 | arm_low（底部武装线） | arm_high（顶部武装线） | 备注 |
|---|---|---|---|
| 便宜 | 30（放宽） | 85（收紧） | 便宜时更积极抄底，更不容易卖飞 |
| 合理 | 20 | 80 | 基准 |
| 昂贵 | 15（收紧） | 75（放宽） | 昂贵时触发的 BUY 降级为"观察"提醒 |

### 4.4 事件类型

`ARMED_BOTTOM`、`ARMED_TOP`、`BUY_DIP`、`SELL_PEAK`、`DISARMED`、`VALUATION_TIER_CHANGE`、`DATA_DEGRADED`

## 5. 数据模型（SQLite，纯 Go 驱动 `modernc.org/sqlite`，免 CGO）

```sql
-- 原始指标：长表。换数据源、加减指标都不用改表结构
-- 同一指标可以同时保存多个来源的数据，用于重叠对比；引擎按路由优先级取第一个有值的来源
CREATE TABLE raw_metric (
  metric     TEXT NOT NULL,          -- 标准指标 ID（§6.1），如 'cn.hs300.close'、'cn.hs300.pe_ttm'、'cn.bond.y10'
  trade_date TEXT NOT NULL,          -- YYYY-MM-DD，按该市场本地时区
  source     TEXT NOT NULL,          -- 插件名，如 'eastmoney'
  value      REAL NOT NULL,
  fetched_at TEXT NOT NULL,
  PRIMARY KEY (metric, trade_date, source)
) WITHOUT ROWID;

-- 个股后复权收盘价（仅用于算广度；后复权的历史值不随除权改变，只追加不改写）
CREATE TABLE stock_close (
  code TEXT NOT NULL, trade_date TEXT NOT NULL, close_hfq REAL NOT NULL,
  PRIMARY KEY (code, trade_date)
) WITHOUT ROWID;
CREATE TABLE stock_meta (code TEXT PRIMARY KEY, name TEXT, list_date TEXT, delist_date TEXT);

-- 衍生得分：可以从 raw_metric + 参数完全重算
CREATE TABLE score_daily (
  market TEXT, trade_date TEXT, params_version TEXT,
  v REAL, valuation_tier TEXT,
  t1 REAL, t2 REAL, t3 REAL, t4 REAL, t_base REAL, t_pct REAL, t_s REAL,
  n_low INT, n_high INT, degraded INT, state TEXT,
  PRIMARY KEY (market, trade_date, params_version)
);

CREATE TABLE signal_event (
  id INTEGER PRIMARY KEY, market TEXT, trade_date TEXT, params_version TEXT,
  event TEXT, payload_json TEXT, notified_at TEXT
);

CREATE TABLE job_run (id INTEGER PRIMARY KEY, job TEXT, trade_date TEXT, status TEXT, progress REAL, detail TEXT, started_at TEXT, finished_at TEXT);

-- Web 可编辑的配置
CREATE TABLE param_set (version TEXT PRIMARY KEY, name TEXT, params_json TEXT NOT NULL, is_active INT DEFAULT 0, created_at TEXT);
CREATE TABLE notify_channel (id INTEGER PRIMARY KEY, kind TEXT NOT NULL, name TEXT, config_json TEXT NOT NULL, enabled INT DEFAULT 1);  -- webhook/secret 在 API 响应中打码
CREATE TABLE web_session (token_hash TEXT PRIMARY KEY, created_at TEXT, expires_at TEXT);
```

- `params_version` 取配置参数的 hash。改参数后重算，新旧结果并存，方便对比。
- **个股日线是我们自己的数据**（2026-11-25 确认）：`stock_list` + `stock_bar(code, d, close, mult, source)`，
  `close` 为不复权收盘价，`mult` 为当日除权乘数（后复权链式计算：`hfq_t = hfq_{t-1} × close_t × mult_t / close_{t-1}`）。
  任何个股数据源只需提供“不复权收盘 + 除权乘数”即可接入（如快照源：`mult_t = close_{t-1} / 前收_t`）。
  市场广度只读本地日线，数据源不可用时仍可全量重算。
- **广度历史回填**（一次性，旧方案，已被上一条取代）：约 5,900 只在市股票 + 退市股，逐只拉取腾讯 `fqkline` 后复权日线
  （按约 2.5 年一段分页），预计 1–2 小时。支持断点续传，并限制并发。
- **广度每日增量**：只用 `push2` 全市场快照（约 60 次请求）取今收 `C_t` 和前收 `P_t`。
  交易所公布的前收已经做过除权调整，因此 `hfq_t = hfq_{t-1} × C_t / P_t`，无需重拉历史。
  每月抽样 50 只股票，与腾讯后复权数据比对，校验累计误差。
- 广度是最重、最脆弱的一维，放在 M4 实现；在它就绪之前，参数集不启用 T3，引擎用 T1/T2/T4 三维跑通。

## 6. 工程架构（Go 后端 + React 前端，单二进制）


### 6.1 数据插件层

**核心思想**：引擎只消费"标准指标"（metric），不关心数据从哪来。数据源以插件形式提供指标，由配置决定路由和回退顺序。

```go
// 时间序列类数据源（指数、PE、利率、两融……）
type Source interface {
    Name() string
    Provides() []MetricID                                  // 能提供哪些标准指标
    Fetch(ctx context.Context, m MetricID, from, to Date) ([]Point, error)
}

// 个股类能力（只用于计算广度这类"由个股派生"的指标），拆成小接口，插件按需实现：
type StockLister   interface { ListStocks(ctx context.Context, market string, includeDelisted bool) ([]Stock, error) } // 交易所插件
type BarFetcher    interface { FetchBars(ctx context.Context, code string, from, to Date) ([]Bar, error) }              // 腾讯：后复权日线
type SnapshotTaker interface { Snapshot(ctx context.Context, market string) ([]Quote, error) }                          // 东财 push2：今收 + 前收

func Register(name string, factory func(cfg map[string]any) (Source, error))
```

- **未完成数据由插件负责过滤**：插件只返回已收盘的数据（例如 15:30 前不返回当日 bar），引擎无需关心。
- **标准指标目录**：命名形如 `cn.hs300.close`、`cn.hs300.pe_ttm`、`cn.bond.y10`、`cn.csiall.turnover`、`cn.margin.buy_amount`、`cn.market.amount`。
  每个指标在目录中声明单位、频率、发布时滞（如两融为 T+1）。
- **配置路由与回退**：
  ```yaml
  sources:
    cn.hs300.close:   [eastmoney, tencent]   # 主源失败时自动尝试下一个
    cn.hs300.pe_ttm:  [csindex]
    cn.bond.y10:      [eastmoney]
  ```
- **离线数据优先用于历史回填**（2026-11-25 用户要求）：回测只读本地 SQLite，不在回测时拉线上数据；
  历史数据的获取也优先走本地离线数据集或文件导入，在线接口主要用于每日增量。
  候选离线源：`free-stockdb`（本地 LevelDB + HTTP JSON 接口 `127.0.0.1:7899`，2000 年起前复权日线，
  含 `pre_close`、`float_mv`、`pe_ttm`、`is_st`），作为 M4 广度历史回填的主源（腾讯为备用）。
  待核实：是否包含已退市股票（幸存者偏差）、前复权是否为等比复权、数据截止日期与更新方式。
- **三种插件形态**：
  1. **内置 Go 插件**：编译进二进制，用 `init()` 注册。性能最好，是首期主力。
  2. **exec 外部插件**：调用任意可执行程序或脚本，例如用 Python 写的 akshare 采集脚本，约定标准输入输出的 JSON 协议，不用改 Go 代码就能接入。
  3. **CSV 导入**：从 Web 上传或指定目录导入，用于手工补数、接入付费数据导出。
  > 不使用 Go 原生 `plugin` 包：它不支持 Windows，且对编译版本要求严格。
- **路由规则**：只有口径一致的来源才能放在同一指标的路由里；口径不同就另立指标。
  例如中证全指成交额与"上证+深证成指"成交额口径不同，所以另立 `cn.csiall.amount`，不作为 `cn.market.amount` 的备用源。
- **派生指标**：在 Go 代码中注册（输入指标 + 计算函数），如 `cn.margin.buy_ratio`、`cn.breadth.ma200`，不做表达式解析器。
- 每条入库数据都记录 `source`。主源切换后，Web 上可以查看各来源数据的重叠对比。如果差异超出阈值，提示需要重新计算分位。

### 6.2 市场定义（为美股等其他市场预留）

引擎按"角色"取数，市场定义负责把角色映射到具体指标。新增市场时只需要新增一份市场定义，以及对应的数据源插件：

```yaml
markets:
  CN:
    timezone: Asia/Shanghai
    calendar_ref: cn.hs300.close          # 有该指标数据的日子即为交易日
    roles:
      index_close:  cn.hs300.close
      pe_ttm:       cn.hs300.pe_ttm
      bond_y10:     cn.bond.y10
      heat:         derived:cn.market.turnover_value   # T1，派生 = 中证全指成交额(T) / 全A流通市值(T-1)
      leverage:     derived:cn.margin.buy_ratio        # T2，派生 = 融资买入额 / 中证全指成交额（T-1）
      breadth:      derived:breadth_ma200 # T3，由个股数据派生
  # US（第二阶段）：heat→CBOE PCR、leverage→VIX……角色不变，映射不同
```

### 6.3 Web（主要交互方式）

Go 提供 JSON API，并通过 `embed` 托管前端构建产物，部署产物仍是**一个二进制加一个 SQLite 文件**。

| 页面 | 内容 |
|---|---|
| 总览 | 当前估值档、择时温度仪表盘、四维得分、状态机状态（是否武装、武装天数）、数据健康度 |
| 历史 | 指数价格、T_s、V 的联动折线图，带信号标记，支持缩放和时间区间选择 |
| 信号 | 事件列表（武装、触发、失效、降级），可展开查看当日快照 |
| 回测 | 在表单里调参数 → 运行 → 输出信号表、前瞻收益分布、基线对比、相关矩阵；参数集可保存为 `params_version`，设为"生效"后实盘使用 |
| 数据 | 各指标的覆盖区间、最新日期、来源；触发回填、重算，并显示进度；查看任务日志 |
| 设置 | 推送渠道的增删改和测试发送、调度时间 |

- **鉴权**：部署在公网，必须登录。单管理员口令（bcrypt 哈希存在 config.yaml）+ HttpOnly、`SameSite=Lax` 会话 Cookie；
  登录失败限速；写接口校验 `Origin`；HTTPS 由反向代理（Caddy/Nginx）负责。
- **安全边界**：exec 外部插件等同于执行任意命令，只能在 config.yaml 中配置，Web 不可修改；CSV 上传限制大小；
  推送渠道的 webhook、secret 在 API 响应中打码。
- **配置的存放位置**：可以在 Web 上修改的内容（推送渠道、参数集、调度时间）存 DB；
  启动级配置（监听地址、DB 路径、口令哈希、代理、数据源路由）放 config.yaml。
- 回填等耗时任务在后台运行，前端轮询进度，同一时间只允许运行一个回填任务。
- CLI 保留 `backfill`、`run`、`backtest` 子命令，供调试和运维使用，与 Web 共用 job 层代码。

### 6.4 运行与调度

- **调度**：`mt serve` 内置 cron。A股任务每个交易日 17:30 开始，做数据完整性检查，不完整则每 30 分钟重试，22:00 截止。
  两融数据 T+1 发布，T2 按设计统一使用 T-1 值，回测采用同一口径。
- **交易日判断**：以沪深300 日线当日是否有数据为准，不额外维护交易日历。
  该判断只能在 15:30 以后进行：东财盘中也会返回当日未完成的 bar（§2 坑 3）。
- **幂等**：`run --date=YYYY-MM-DD` 可以重复执行，结果一致；推送按 `signal_event.notified_at` 去重。
- **部署**：大陆云服务器（东财、中证接口访问稳定）；Telegram 在大陆被墙，`telegram` notifier 支持配置 HTTP 代理，或指向海外服务器的转发。
- 单二进制 + 一个 SQLite 文件，可选 Docker。

## 8. 回测与验收

- **区间**：2014-01 至今。**样本外检验**：用 2014–2020 校准参数，用 2021 至今验证，不再回调。
- **评估指标**（按信号统计）：触发后 20/60/120 日前瞻收益的分布（中位数、胜率）、最大不利偏移、信号次数。
- **基线对比**：① 只看估值层（V≤30 买入、V≥70 卖出）；② 沪深300 MA200 择时；③ 买入持有。
- **稳健性**：主要阈值 ±20% 扰动后结论不变，才算通过；扰动后结果大起大落，说明过拟合。
- **严禁未来函数**：分位窗口、动态周K、两融 T-1、PE 前值填充，全部按"当时可得"的口径计算。
- 信号频率只作为参考（预期每年 1–3 次），不作为校准目标。

## 10. 风险与待定

- 东财、中证均为非官方/公开网页接口，可能改版或限流 → collector 适配器化，每次抓取做 schema 校验，失败时告警。
- 沪深300 PE 2011 年以前没有数据，限制了估值层的历史深度；10 年窗口要到 2021 年后才满窗，之前用扩展窗口（§3.4）。
- 广度的退市清单完整性：上交所返回 145 条，深交所接口待调通，两者需合并校验。缺失退市股会带来幸存者偏差，使历史广度偏高。
- 以下均为初始猜测，必须由 M3 回测决定：
  - 四维等权
  - 估值三档对应的武装线（§4.3）
  - 触发阈值 8/5 分
  - 武装 60 日超时
  - 冷却复位线 35/65
- **M4 结果**：本地库 5,557 只 A 股（含退市 333 只，2022–2024 年每年 42–49 只，与实际相符），1,591 万行日线，数据库约 780MB；
  stockdb 回填 4 分 33 秒，广度全量计算 17 秒。广度抽查：2015-06 顶 99.7%、2016-01 熔断 7.6%、2018 年底 7.5–10%、2024-02 4.6%、2024-10 90%。
  T3 与其他维度相关系数 0.55–0.63。**加入 T3（四维等权）并未改善温度计信号**：总收益 -3.4% → -8.8%（平滑 5 日时 +13.0% → +3.4%），
  仍远低于估值档基线 +104.9%。说明问题在信号机制，不在数据维度；生效参数暂保持 T3 权重为 0。
- **M3 回测结论（默认参数，2014-01 至 2026-11）**：
  | 策略 | 总收益 | 年化 | 最大回撤 | 持仓占比 |
  |---|---|---|---|---|
  | 温度计信号持仓 | -3.4% | -0.3% | -37.5% | 25% |
  | 估值档持仓（便宜买、昂贵卖） | +104.9% | +5.9% | -29.7% | 49% |
  | 200 日均线择时 | +99.5% | +5.7% | -33.1% | 55% |
  | 买入持有 | +70.7% | +4.4% | -46.7% | 100% |
  - 温度计底部信号 15 次，120 日收益中位数 -2.6%，低于"任意一天买入"的 +2.7%。主要问题：2014 年估值便宜时连发卖出信号，错过 2015 年牛市；2023 年阴跌中连续 9 次抄底。
  - 结果对参数高度敏感：只把 T_s 平滑从 3 日改为 5 日，总收益就从 -3.4% 变为 +13.0%，说明当前参数不稳健。
  - 样本内（2014–2020）底部信号只有 1 次，统计效力很弱。
  - 维度相关系数：资金热度 / 杠杆情绪 0.61，杠杆情绪 / 价格动量 0.66，资金热度 / 价格动量 0.44，均低于 0.8。
  - 结论：**在完成校准、样本外仍然跑赢估值档基线之前，不应开启实盘信号推送。** 可考虑的方向：估值档作为主仓位、温度计只做加减仓；取消二次分位（方案 C）；顶部信号只在估值昂贵时生效。
- **M2 打分初步观察**（参数未校准）：
  - T_s 的二次分位在持续单边行情中会"适应"：2015 年牛市 T_s 最高点出现在 2014-12，而非 2015-06 的真正顶部；
    2014 年以来 24% 的交易日 T_s ≥ 80、27% ≤ 20。单用 20/80 武装线会过早发出信号，M3 需重点校准（含方案 C 对照）。
  - V 在 2013–2014 年处于扩展窗口早期，样本只有 2 年左右，跳动较大，解读时需谨慎。
  - 全A流通市值 2010-11-08 出现 +12% 的永久性跳升，疑似统计口径变化，只影响 2013 年以前的 T1 分位窗口。
- 相对 v1 删除的内容：期权情绪维度（QVIX 停更、PCR 不可用，改为融资买入占比）、布林 %B（降为回测对照项）、共振乘数修正。
