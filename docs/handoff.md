## 提示词

你接手的是 `D:\project\go_project\market-thermometer`：一个 Go + React 的 A 股「市场波段温度计」，目标是逐步演进为**投研与分析平台**。请先完整阅读以下文件再动手：

1. `docs/roadmap.md`：平台规划（核心 vs 插件边界、阶段 P1–P6、交易安全要求）
2. `docs/design.md`：温度计设计、数据源实测结论、回测结论（§2、§9、§10 最重要）
3. `git log --oneline`：20 个按功能边界拆分的提交，能看出模块划分
4. `config.example.yaml`：数据源路由、个股/基金数据源、基金净值源

### 用户与协作约定

- 全程用中文交流；用户偏好 KISS、渐进式推进，先验证再扩展。
- **Web 是主要交互方式**，CLI 只用于调试运维。
- **除核心功能外都做成插件**（数据源、因子、策略、通知、交易通道、页面扩展）。
- **数据是我们自己的**：外部数据（stockdb、腾讯、东财、中证）只是可替换的来源，统一同步进本地 SQLite；派生指标只从本地数据计算。历史回填优先用离线数据，在线接口主要用于每日增量。
- 免费数据源优先，付费源（Tushare 等）等项目有收益后再说；新增依赖或付费服务前先问用户。
- **git**：按功能点或功能边界提交，每个提交都应能单独编译；提交前跑 `gofmt -l`、`go vet ./...`、`go test ./...`，前端改动跑 `cd web && pnpm build`。用户没要求时不要 push。
- 每个阶段做完后停下来向用户汇报：做了什么、如实写出验证结果（哪些在浏览器里实测、哪些只有单测）、需要用户决定的事。

### 已确认的决策（2026-11-25）

- 规划里的阶段顺序已认可：**P1 温度计可用 → P2 插件化重构 → P3 投研 → P4 模拟交易 → P5 实盘 → P6 多市场**。
- P3 投研功能的优先级按建议来：**组合分析 → 行情图 → 财务数据**。
- **券商和交易终端都还没定**：P4 模拟交易的订单、持仓、资金模型必须与券商无关；P5 实盘先不做，交易插件接口只设计、不实现。外部进程插件协议先做到能用 Python 写插件（将来 QMT / PTrade 一类终端多是 Python）。

### 必须知道的坑

- **东财 `push2his`（K 线）会封 IP**，封禁可升级到 1 小时以上：核心指标已不依赖它，插件不重试、失败后短路 10 分钟。`push2`、`datacenter` 不受影响。
- **stockdb**（`D:\Program Files\stockdb`，本地 `127.0.0.1:7899`，详见记忆或 `internal/datasource/stockdb` 的注释）：
  - 闭源程序，**不要替用户运行**它的 exe / pyd，需要时请用户启动；
  - 请求必须带 `json=1`；键里的 `:` 和 `,` 不能百分号编码；
  - **绝不能发全市场查询（`k1=*`）**：会卡死服务端，内存涨到 16GB，只能重启；
  - 当天和最近几天的数据是临时值（24:00 才校对），所以同步每次往回重拉约 10 个交易日，市场广度每次全量重算；
  - `pre_close` 字段口径不对，不要用。
- **腾讯 `fqkline`**：「后复权」序列口径不一致，不要用；除权乘数从分红送转标注计算，ETF 分红没有标注。大量请求会被 WAF 拦截（501）。
- **开发环境**：Windows + Git Bash / PowerShell。
  - 用 Bash 内嵌 Python 改文件时，长脚本容易被 shell 引号打断，优先写成独立脚本文件再执行；脚本里先校验所有替换都能匹配，再写盘。
  - LSP 诊断经常是旧缓存，以 `go build` / `go vet` 的结果为准。
  - 用 `go build -o mt.exe` 替换正在运行的程序会留下 `mt.exe~`（已在 .gitignore 中）。
- **登录口令**：本地 `config.yaml` 里是一个临时口令的哈希，开发用的明文口令在已失效会话的 scratchpad 里，可能已经没有了。需要登录时请用户运行 `mt.exe hashpw` 生成新口令，或者你重新生成一个临时口令并告诉用户。
- 后台运行的 `mt.exe serve` 会随上一个会话结束，需要时重新启动：`cd D:\project\go_project\market-thermometer && ./mt.exe serve`，地址 http://127.0.0.1:8080 。
